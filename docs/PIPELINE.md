# 3D production pipeline

## Purpose

This repository treats character source, validation and animation as one reproducible production chain while keeping each boundary independently testable.

```text
Character reference
      ↓
Editable Blender source
      ↓
Sculpt / materials
      ↓
Sculpt metrics + multi-view QA
      ↓
Rigging / skin weights
      ↓
Deformation QA + anatomical skinning gate
      ↓
Validated GLB
      ↓
React Three Fiber / Remotion runtime
      ↓
Deterministic performance + camera + lighting
      ↓
Film render
```

## Character source

`characters/<name>/blender/` owns scripts that create or mutate editable Blender source. A `.blend` is the authoritative editable state once its corresponding QA gates have been accepted.

Character-specific validation lives in `characters/<name>/validation/`. Validators are production gates, not score-adjustment utilities: when a candidate fails, the model/source is changed rather than weakening thresholds to obtain a pass.

## Rat sculpt gate

The Rat v3 sculpt validator evaluates the production manifest for refinement stage, visual QA flags and geometric proportions. The latest PR #8 candidate generated successfully but remained below the accepted gate for muzzle projection and shoulder-to-waist taper. That failure is preserved as a real quality signal.

## Rigging and skinning

`characters/rat/rigging/repair_skin_weights_blender.py` contains the newer hybrid weight-repair approach. `characters/rat/validation/validate_skin_semantics_v3.py` checks anatomical influence distributions across the body, hoodie and trousers and also verifies skin-weight normalization.

A repaired migration snapshot already passes this semantic gate. The outstanding production task is to reproduce that repair from the authoritative editable Blender source in Blender itself, render the deformation poses, export a new GLB, and confirm that the new export passes the same validator.

## Runtime contract

The production GLB contract uses stable named bones for hips, chest, neck, head, jaw, arms, legs, eyes, brows, ears and tail segments. The Remotion runtime maps deterministic `PerformancePose` data to those bones per frame.

This separation is intentional:

- Blender owns geometry, materials, armature and weights.
- the GLB is the interchange artifact;
- React Three Fiber owns scene/runtime loading;
- Remotion owns deterministic frame-driven choreography, cinematography and rendering.

## Rat + Dog film

`films/rat-dog/` owns the reusable performance/camera/lighting system and the Rat + Dog film composition. Prototype models may be regenerated by its model builder. Production character GLBs should replace prototypes without requiring choreography or camera rewrites.

## CI model

Fast validation runs without Blender and must cover:

- Python syntax/compile checks;
- deterministic animation/performance tests;
- Remotion architecture/contract tests;
- semantic GLB validation when the corresponding validated artifact is present;
- tracked-secret and generated-file hygiene.

Blender validation is a separate, heavier workflow. It must start from repository-owned authoritative source rather than a hard-coded historical workflow run. Blender downloads are checksum-verified before extraction. Generated renders, videos and candidate exports are workflow artifacts with short retention unless explicitly promoted to accepted source/QA evidence.

## Security requirements

- GitHub Actions are pinned to immutable commit SHAs.
- checkout uses `persist-credentials: false` unless a narrowly documented migration-only write step requires otherwise.
- normal workflows use read-only repository permissions.
- no credentials, API tokens, signing material or `.env` secret files are committed.
- external binary downloads are integrity-checked before execution/extraction.
